Why Web MIDI Breaks at 4,134 Bytes (And the 1983 Bit-Packing Trick That Fixed It)

Web MIDI is a minor miracle. You open a browser tab, plug a synthesizer built in 1983 into a USB port, and raw hexadecimal streams directly into JavaScript memory. Then your bank dump silently cuts off at patch 26 every single time.

When building browser-based SysEx tools, you quickly realize that modern web APIs and vintage serial protocols speak two entirely different dialects of physics. Here is the story of how 40-year-old serial protocol constraints collided with modern browser stream accumulation—and why 8-to-7 bit MSB unpacking is still the most fascinating hack in music technology.

1. The 7-Bit Curse of 1983

In 1983, Dave Smith and Roland engineers established the MIDI 1.0 specification with one inviolable rule:

Rule #1 of MIDI: The Most Significant Bit (Bit 7) is strictly reserved for Status Bytes.

If a byte has 0b1xxxxxxx (values 0x80 to 0xFF), it is a command—like Note On (0x90), Clock (0xF8), or SysEx Start (0xF0).

If a byte has 0b0xxxxxxx (values 0x00 to 0x7F), it is Data.

+---+---+---+---+---+---+---+---+ | 0 | D6| D5| D4| D3| D2| D1| D0| --> Valid MIDI Data Byte (Max value 127) +---+---+---+---+---+---+---+---+

This created an immediate dilemma for synthesizer manufacturers: How do you transmit full 8-bit parameter values (0–255) or raw ASCII patch names across a wire that only allows 7 bits per byte?

Their solution was ingenious: 8-to-7 Bit MSB Packing.

Instead of sending raw 8-bit bytes, you strip the 8th bit off 7 consecutive data bytes, pack those 7 high bits into an 8th "leader" byte, and transmit an 8-byte frame across the wire:

[MSB Leader: b0 b1 b2 b3 b4 b5 b6] + [Byte 0 (7-bit)] + [Byte 1 (7-bit)] ... [Byte 6 (7-bit)]

When you parse a Sequential Prophet-5, Prophet-6, or OB-6 dump in Python or JavaScript, if you don't reconstruct that 8th bit for every 7-byte block, every preset name comes out as unreadable gibberish:

def unescape_sequential(sysex: bytes) -> bytes: result = bytearray() idx = 0 while idx < len(sysex): msbits = sysex[idx] idx += 1 for i in range(7): if idx < len(sysex): # Restore the stripped 8th bit from the MSB leader byte result.append(sysex[idx] | ((msbits & (1 << i)) << (7 - i))) idx += 1 return bytes(result)
Remember this: If your hardware dump looks corrupted in a hex editor, you aren't looking at bad data. You are looking at a 7-bit packing matrix designed during the Reagan administration.

2. Why Chrome's Stream Accumulator Choked at Byte 4,134

Most Web MIDI code examples online assume synths dump soundbanks in single, contiguous blocks. A Yamaha DX7 dumps exactly 4,104 bytes in one shot (32 voices × 128 bytes + headers).

Because of this, legacy ingestion logic frequently relies on a naive byte-count check:

// The classic naive auto-detect accumulator const expectedSize = 4104; if (lastByte === 0xF7 && ingestedBytes.length >= expectedSize - 100) { stopMidiIngestion(true); // Close the stream! }

Now plug in a Sequential Prophet-5 (Rev 4). The Prophet-5 doesn't send one monolithic 4KB chunk. It transmits 40 separate, distinct SysEx messages back-to-back—one message per patch, clocked at approximately 159 bytes each.

Do the math:

Patch 1 to 25 = 25 × 159 = 3,975 bytes Patch 26 = 26 × 159 = 4,134 bytes (>= 4,004 threshold!)

The exact millisecond the 26th patch arrived, ingestedBytes.length hit 4,134. The accumulator saw a closing 0xF7 delimiter, matched the condition, assumed a DX7 dump had finished, and forcefully slammed the stream shut.

Patches 27 through 40 vanished into the ether.

3. The 3 Rules for Robust Web MIDI Ingestion

To build browser-based Web MIDI tools that never drop hardware patches, follow these three rules:

  1. Inspect Manufacturer ID Bytes, Not Lengths: Check byte data[1] on incoming packets (0x01 for Sequential, 0x41 for Roland, 0x43 for Yamaha). Never assume uniform bank dimensions.
  2. Debounced Ingestion Idle Timers Beat Message Counters: Hardware DIN-to-USB optocouplers introduce microsecond latency. Using a 25-second debounced silence detector allows multi-message dumps to complete organically without premature cutoffs.
  3. Unbundle 30-Year-Old Native Utilities: Musicians shouldn't need to run 32-bit legacy executables just to backup soundbanks. With modern Web MIDI, WebAssembly, and local SQLite/PostgreSQL caching, zero-install studio workflows in the browser are finally production-ready.
